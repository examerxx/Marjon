> **Платформа:** Windows 10/11 (64-bit)  
> **Версия:** 2.0 (расширенная — мультирежимное приложение)

## 1. Общая информация

### 1.1. Назначение

Desktop Terminal — **мультирежимное приложение для всего персонала ресторана**, устанавливаемое на компьютер/моноблок. Включает режимы: Кассир, Официант, Кухня (KDS), Бар.

**Ключевое отличие от web-версии:**
- Нативный EXE-файл — не требует браузера
- Оптимизировано под сенсорный экран (touch) моноблоков
- Работает в офлайн-режиме (локальный кэш + синхронизация)
- Полноэкранный режим (kiosk mode)
- Быстрее запускается и потребляет меньше ресурсов
- Быстрый вход (PIN-код) для смены кассиров/официантов
- Прямая печать на ESC/POS принтеры через TCP

### 1.2. Целевые пользователи

| Роль | Режим | Задачи | Навыки |
|------|-------|--------|--------|
| **Кассир** | Cashier | Приём заказов, оплата, чеки | Средние |
| **Официант** | Waiter | Создание заказов по столам, контроль | Средние |
| **Повар** | Kitchen | Просмотр заказов, отметка готовности | Базовые (tap по экрану) |
| **Шеф-повар** | Kitchen | Заказы + техкарты + стоп-лист + статистика | Средние |
| **Бармен** | Bar | Заказы напитков, отметка готовности | Базовые |

### 1.3. Технологический стек

| Компонент | Технология | Обоснование |
|-----------|-----------|-------------|
| Runtime | **Electron** (Node.js + Chromium) | Переиспользование React-компонентов из web, быстрая разработка |
| UI | React 18 | Те же компоненты, что в web-панели |
| Real-time | WebSocket | Мгновенное получение заказов |
| Offline | SQLite (better-sqlite3) | Локальный кэш заказов при потере связи |
| Audio | Web Audio API | Звуковые уведомления |
| Build | electron-builder | Сборка в .exe (NSIS installer) |
| Auto-update | electron-updater | Автообновление через GitHub Releases |

**Почему Electron, а не нативное приложение:**
- Переиспользование 80% кода из web KDS (`KitchenPage.jsx`)
- Один разработчик может поддерживать и web, и desktop
- Cross-platform потенциал (Linux для дешёвых мини-ПК в будущем)
- Electron = стандарт для KDS (VS Code, Slack, Discord — все на Electron)
- Аналоги (Тиллипад KDS, Delivety KDS) используют похожие подходы

## 3. Офлайн-режим

### 3.1. Сценарий потери связи

```
Связь есть:
  Заказы приходят по WebSocket → отображаются мгновенно
  Статусы отправляются через REST API

Связь потеряна:
  1. Показать индикатор «ОФЛАЙН» (красная полоса сверху)
  2. Показать последние кэшированные заказы из SQLite
  3. Статусы (готово/принято) сохраняются локально
  
Связь восстановлена:
  1. Автоматическая синхронизация всех локальных статусов
  2. Загрузка пропущенных заказов
  3. Скрыть индикатор «ОФЛАЙН»
  4. Звуковой сигнал о восстановлении
```

### 3.2. Локальный кэш

| Данные | Хранилище | Время жизни |
|--------|-----------|-------------|
| Активные заказы | SQLite | До закрытия смены |
| Меню (блюда, техкарты) | SQLite | 24 часа, обновление при запуске |
| Стоп-лист | SQLite | Синхронизация каждые 5 мин |
| Настройки станции | JSON-файл | Постоянно |
| Статусы (ожидание синхронизации) | SQLite | До успешной отправки |

## 5. Настройки

### 5.1. Первоначальная настройка

При первом запуске:

1. **Ввод URL сервера** (или выбор из списка по QR-коду)
2. **Авторизация** (телефон + пароль повара/шеф-повара)

## 6. Интеграция с бэкендом

### 6.1. REST API

| Endpoint | Method | Описание |
|----------|--------|----------|
| `/auth/login` | POST | Авторизация повара |
| `/kitchen/orders` | GET | Получить активные заказы |
| `/kitchen/orders/{id}/status` | PATCH | Обновить статус заказа |
| `/kitchen/orders/{id}/items/{item_id}/status` | PATCH | Обновить статус блюда |
| `/kitchen/stations` | GET | Список станций |
| `/inventory/products/{id}/recipe` | GET | Техкарта блюда |
| `/inventory/stop-list` | GET | Стоп-лист |
| `/inventory/stop-list` | POST | Добавить в стоп-лист |

### 6.2. WebSocket

```
ws://{server}/ws/kitchen?station={station_id}&token={jwt}

Входящие события:
- new_order      → Новый заказ
- order_updated  → Изменение заказа (дозаказ, отмена позиции)
- order_cancelled → Заказ отменён
- stop_list_updated → Обновление стоп-листа

Исходящие события:
- item_status_changed → Блюдо: ожидает → готовится → готово
- order_completed     → Весь заказ готов
- order_accepted      → Заказ принят в работу
```

### 6.3. Heartbeat

- Приложение отправляет `ping` каждые 15 секунд
- Если нет `pong` в течение 30 секунд → переключение в офлайн
- При восстановлении → автоматическая повторная подписка

## 7. Установка и обновление

### 7.1. Дистрибуция

| Формат | Описание |
|--------|----------|
| **EXE installer** (NSIS) | Установщик для Windows (основной) |
| **Portable** (.zip) | Без установки, запуск из папки (для тестов) |
| **MSI** (опционально) | Для корпоративного деплоя через GPO |

### 7.2. Установка

1. Скачать `Marjon-Kitchen-Setup-1.0.0.exe` с сайта или через web-панель
2. Запустить установщик (Next → Next → Install)
3. Ярлык на рабочем столе: «Marjon Kitchen»
4. Первый запуск → настройка (см. раздел 5.1)

### 7.3. Автообновление

```
При запуске:
  1. Проверить наличие обновления на сервере
  2. Если есть → скачать в фоне
  3. Показать баннер "Доступно обновление"
  4. Установить при следующем перезапуске
  
Принудительное обновление:
  Для критических версий — блокировка работы до обновления
```

### 12.3. Режимы приложения (расширение vs ТЗ)

> ZimZim имеет единое приложение для всех ролей. Мы делаем так же, но с **выделенными специализированными режимами**.

| Режим | Основная задача | Целевой пользователь |
|-------|----------------|---------------------|
| **Кассир** | Приём заказов, оплата, чеки | Кассир |
| **Кухня (KDS)** | Очередь заказов, таймеры, готовность | Повар / Шеф |
| **Официант** | Столы, заказы, статусы | Официант |
| **Бар** | Напитки, коктейли | Бармен |

Каждый режим — полноэкранный, оптимизированный под свою задачу.
