## 1. Общая информация

### 1.1. Назначение

Мобильное приложение Marjon — рабочий инструмент для персонала в зале ресторана и удалённого контроля для владельца. НЕ является приложением для гостей (QR-меню — отдельный продукт).

### 1.2. Целевые пользователи

| Роль | Основное использование | Частота |
|------|----------------------|---------|
| **Официант** | Приём заказов у столика, статус кухни | Постоянно (8 часов/день) |
| **Владелец** | Дашборд, уведомления, контроль выручки | Периодически (5–10 раз/день) |
| **Курьер** | Список доставок, навигация, статусы | Постоянно (во время доставок) |
| **Менеджер** | Отчёты, персонал, оперативное управление | Периодически |

### 1.3. Технологический стек

| Компонент | Технология | Обоснование |
|-----------|-----------|-------------|
| Framework | **React Native** + Expo | Единый код для iOS/Android, переиспользование логики из web |
| Navigation | React Navigation v6 | Стандарт для React Native |
| State | Zustand или React Context | Лёгкий state management |
| HTTP | Axios (тот же `api/client.js`) | Единый API-клиент с web |
| Real-time | WebSocket (native) | Уведомления о готовности блюд |
| Storage | AsyncStorage + SQLite | Офлайн-кэш заказов |
| Push | Expo Notifications + FCM/APNs | Push-уведомления |
| Maps | React Native Maps | Зоны доставки, GPS курьера |

### 1.4. Системные требования

| Платформа | Минимальная версия | Целевые устройства |
|-----------|-------------------|-------------------|
| iOS | 15.0+ | iPhone 8+, iPad (опционально) |
| Android | 8.0 (API 26)+ | Любой с 2GB+ RAM |

## 2. Приложения по ролям

### 2.1. Архитектура: одно приложение vs раздельные

**Решение: одно приложение** с экраном выбора роли после авторизации.

**Обоснование:**
- Проще в обслуживании (один codebase, один релиз)
- Владелец может переключаться между ролями
- Меньше нагрузка на поддержку (1 приложение в сторах)
- ZimZim делает 4 приложения — это их слабость (фрагментация)
- Paloma365 делает 2 (POS + Waiter) — разумнее, но всё равно фрагментировано

```
┌─────────────────────────────────┐
│         MARJON App              │
│                                 │
│  ┌───────────────────────────┐  │
│  │     Login Screen          │  │
│  │     (телефон + пароль)    │  │
│  └────────────┬──────────────┘  │
│               │                 │
│  ┌────────────▼──────────────┐  │
│  │     Role Selector         │  │
│  │  [Официант] [Владелец]    │  │
│  │  [Курьер]  [Менеджер]     │  │
│  └────────────┬──────────────┘  │
│               │                 │
│  ┌────────────▼──────────────┐  │
```

## 3. Экраны: Официант

### 3.1. Навигация

```
Tab Bar (bottom):
├── Столы (карта зала)
├── Мои заказы (список активных)
├── Меню (каталог для быстрого заказа)
└── Уведомления (готовность блюд)
```

### 3.2. Карта столов

| Элемент | Описание |
|---------|----------|
| Визуальная карта | Схема зала с расположением столов |
| Статус стола | Зелёный (свободен), Красный (занят), Жёлтый (ожидает оплату) |
| Tap на стол | Открыть заказ стола или создать новый |
| Фильтр | Мои столы / Все столы |

### 3.3. Создание заказа

**Сценарий (happy path):**

1. Официант нажимает на свободный стол
2. Открывается каталог меню (категории → блюда)
3. Tap на блюдо → добавить в заказ (количество, модификаторы, комментарий)
4. Просмотр корзины (итого, скидка)
5. Кнопка «Отправить на кухню» → заказ уходит через API
6. Кухня получает заказ через WebSocket
7. Официант видит статус заказа в реальном времени

**UI:**
- Категории — горизонтальный скролл (tabs)
- Блюда — карточки с фото, название, цена
- Корзина — bottom sheet, можно свайпнуть для удаления
- Кнопка «Отправить» — большая, зелёная (teal), одним тапом

### 3.4. Мои заказы

| Элемент | Описание |
|---------|----------|
| Список | Карточки заказов (стол, время, сумма, статус) |
| Статус | Цветовая индикация: Новый / Готовится / Готов / Оплачен |
| Действия | Дозаказ, закрыть счёт, перенести стол |
| Push | Уведомление при готовности блюда |

### 3.5. Уведомления

- Push-уведомление при готовности заказа
- Вибрация + звук
- In-app badge на табе «Уведомления»
- История уведомлений за смену

### 3.6. Офлайн-режим

**Критично для ресторанов с плохим Wi-Fi:**

- Заказы сохраняются локально (SQLite)
- При восстановлении связи — автоматическая синхронизация
- Визуальный индикатор «Офлайн» в header
- Меню кэшируется при запуске приложения

## 4. Экраны: Владелец

### 4.1. Навигация

```
Tab Bar (bottom):
├── Дашборд (KPI, графики)
├── Заказы (все активные заказы)
├── Отчёты (быстрые отчёты)
└── Ещё (настройки, персонал, склад)
```

### 4.2. Дашборд

Мобильная версия OwnerDashboard:

**Карточки KPI (2x2 grid):**
- Выручка сегодня
- Количество заказов
- Средний чек
- Открытые столы

**Графики:**
- Мини-график выручки за 7 дней (sparkline)
- Топ-5 блюд (горизонтальный бар)

**Pull-to-refresh** для обновления данных.

### 4.3. Быстрые отчёты

Упрощённые версии web-отчётов:
- Z-отчёт за текущую смену
- Выручка по дням (список)
- Топ-блюда за период
- Активность персонала

### 4.4. Push-уведомления для владельца

| Событие | Уведомление |
|---------|------------|
| Крупный заказ (> X UZS) | «Новый заказ на 500 000 UZS (стол 7)» |
| Отмена заказа | «Заказ #1048 отменён. Причина: ...» |
| Низкий остаток | «Остаток "Говядина" ниже минимума» |
| Смена открыта/закрыта | «Кассир Алишер открыл смену в 09:02» |
| Конец подписки | «Подписка истекает через 3 дня» |

## 7. Технические требования

### 7.1. Производительность

| Метрика | Значение |
|---------|---------|
| Cold start | < 3 секунды |
| Переход между экранами | < 300 мс |
| Создание заказа (от tap до отправки) | < 5 секунд |
| Потребление памяти | < 150 MB |
| Размер APK/IPA | < 50 MB |

### 7.2. Безопасность

| Требование | Решение |
|-----------|---------|
| Хранение токенов | iOS Keychain / Android EncryptedSharedPreferences |
| SSL Pinning | Для продакшн-API |
| Jailbreak/Root detection | Предупреждение (не блокировка) |
| Session timeout | 8 часов без активности |
| PIN-код приложения | v1.2 (опционально) |

### 7.3. Офлайн-синхронизация

```
Онлайн:
  Создать заказ → POST /pos/orders → OK → обновить UI

Офлайн:
  Создать заказ → Сохранить в SQLite (status: pending_sync)
  [Индикатор "Офлайн" в header]
  
  Связь восстановлена:
  → Получить все pending_sync заказы
  → POST каждый на сервер
  → Обновить status: synced
  → Скрыть индикатор
```
